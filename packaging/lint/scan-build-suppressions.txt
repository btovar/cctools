# Baseline suppressions for packaging/lint/scan-build.sh.

# These are pre-existing clang static analyzer (scan-build) findings across
# all C packages (see the taskvine tech-debt audit's "static analysis"
# item). Captured by checker:file:line so that standing up scan-build in CI
# doesn't fail on day one over debt that predates it. A NEW finding at a
# different location is not covered by these entries and will fail the
# build.

# All entries below were triaged individually (source read against the
# analyzer's own path trace, not just the finding text) across three
# rounds, after the job was first introduced with a larger, unreviewed
# baseline.

# Round 1 (null-pointer / uninitialized-value checkers):
#   - Fixed 6 real bugs: closedir(NULL) in taskvine/src/worker/vine_cache.c,
#     a NULL address passed to strncpy() in
#     work_queue/src/work_queue_worker.c, a NULL dag dereference on an
#     early-failure cleanup path in makeflow/src/makeflow.c, an ignored
#     host_disk_info_get() return value in dttools/src/host_disk_info.c, an
#     ignored rmonitor_server_open_socket() return value in
#     resource_monitor/src/rmonitor_helper_comm.c, and an uninitialized
#     buffer read on an empty hosts file in chirp/src/chirp_matrix.c.
#   - Found that the single largest source of false positives (~30
#     findings) was dttools/src/debug.h's fatal() not being marked
#     __attribute__((noreturn)) -- it never returns (see debug.c), but
#     every "if (x == NULL) fatal(...);" guard looked incomplete to clang
#     without that annotation. Fixed.

# Round 2 (memory-error, security, and the remaining "sounds serious"
# checkers -- double-free, use-after-free, bad-free, unchecked
# setuid/setgid, null function-pointer dereference, dereference of
# undefined pointer, division-by-zero, dangerous VLA declaration, garbage
# branch condition):
#   - Fixed 2 guaranteed double-frees in chirp/src/chirp_client.c (both
#     chirp_client_ticket_get() and chirp_client_ticket_list() had a
#     cleanup loop that freed array entries without ever advancing the
#     array pointer, so it kept re-freeing the same already-freed slot).
#   - Fixed a use-after-free in makeflow/src/makeflow_alloc.c:
#     makeflow_alloc_release_space() could free its own `a` argument via
#     makeflow_alloc_delete() and then immediately dereference it in a
#     trailing stats-printing call.
#   - Fixed a bad free (free() of a string literal) in
#     batch_job/src/batch_file.c, reachable when
#     batch_file_generate_id_dir() is run on a directory containing only
#     "." and ".." entries.
#   - Fixed an uninitialized-struct-field read used as a dlclose() branch
#     condition in dttools/src/hdfs_library.c (hs was malloc'd, not
#     zeroed; reachable via the ordinary misconfiguration of JAVA_HOME set
#     but HADOOP_HOME unset).
#   - Fixed 2 division-by-zero crashes: chirp/src/chirp_multi.c (a chirp
#     multi-volume root server serving an empty/whitespace-only hosts
#     list -- remotely triggerable) and makeflow/src/dag_visitors.c
#     (visualizing a Makeflow file with zero rules).
#   - Fixed a zero-length/off-by-one VLA in chirp/src/chirp_distribute.c:
#     cluster ids are assigned 1..cluster_count but the state array was
#     sized cluster_count (one short), and degenerated to a zero-length
#     VLA whenever the cluster file was missing/empty -- both were
#     out-of-bounds stack writes.
#   - Fixed the setuid()/setgid() pair in dttools/src/username.c: wrong
#     drop order (setuid before setgid, which usually left the group id
#     undropped) and both return values were unchecked. No in-tree caller
#     currently exists for username_set(), so this wasn't an active
#     exposure, but it's exported library API.
#   - Confirmed false positives: both "null function pointer" findings in
#     resource_monitor/src/rminimonitor_helper.c (clang doesn't know
#     syscall(SYS_exit,...) never returns), dttools/src/skip_list.c (clang
#     can't see that sl->level is invariantly non-negative), and a second
#     division-by-zero in makeflow/src/dag_visitors.c (mathematically
#     unreachable given the code's own clamping logic).

# Round 3 (memory-leak and dead-code checkers -- lower bug density per
# finding, so not swept in the first two rounds; triaged via parallel
# subagents each reading the flagged function in full against the
# analyzer's path trace, one round for the 57 memory-leak findings, one
# for the 27 dead-code findings):
#   - Fixed 8 real memory leaks: the final logical-file chunk built by
#     dttools/src/chunk.c's chunk_parse_file() was never linked into the
#     returned chunk_set (a correctness bug, not just a leak -- silently
#     dropped the last file's data on every parse), plus a leak on that
#     function's fopen()-failure path; an EC2 instance-id string leaked
#     once per instance in batch_job/src/batch_queue_amazon.c; per-task
#     side-table structs were never freed in
#     batch_job/src/batch_queue_flux.c and batch_job/src/batch_queue_k8s.c
#     (both accumulate for the life of a long-running manager -- the k8s
#     fix also required zeroing a previously-malloc'd struct field so the
#     new free() path wouldn't free garbage, and capturing a job id by
#     value before freeing the struct it came from, in a caller that
#     otherwise would have read it after the free); dttools/src/rmonitor_poll.c
#     leaked its result struct on a start-time-read failure inside a loop
#     polled every few seconds by taskvine/work_queue's resource
#     reporting; makeflow/src/makeflow_alloc.c's makeflow_alloc_commit_space()
#     leaked an allocation on a grow-failure path that its sibling
#     function (makeflow_alloc_check_space()) already handled correctly;
#     work_queue/src/work_queue.c's work_queue_unblock_host() detached a
#     struct from the blocklist hash table and then just dropped it
#     instead of freeing it, on every unblock for the life of the manager
#     (also drained any hosts still blocked at shutdown, which had the
#     same problem).
#   - Fixed 3 real dead-code/logic bugs found while triaging the
#     "unused code" checkers: chirp/src/chirp_matrix.c discarded the
#     result of three mkdir() calls building a data host's directory
#     structure, silently ignoring remote mkdir failures;
#     deltadb/src/deltadb_stream.c had a stray `continue` in the 'U'
#     (update) record handler that caused every update event whose value
#     failed jx_parse_string() to be silently dropped instead of
#     delivered (copy-paste asymmetry vs. the working 'C' handler just
#     above); makeflow/src/dag_visitors.c computed a file node's
#     size-proportional width for the --change-size XGMML/Cytoscape
#     output but wrote the node before computing it, so the option was
#     silently a no-op for that output format.
#   - Fixed 1 real regression while triaging "dead increment":
#     taskvine/src/manager/vine_manager.c's main wait loop stopped
#     tracking worker disconnects/shutdowns as "events" after a refactor
#     (git blame confirms this check used to exist and was accidentally
#     dropped), which could cause the manager's polling loop to sleep
#     right after actually doing work.
#   - Confirmed real, but low-impact (left as-is, not fixed) --
#     chirp/src/chirp_distribute.c:436,490,648,827 (bandwidth-file/cluster
#     parsing arrays never freed, but chirp_distribute is a one-shot CLI
#     tool); chirp/src/chirp_stream_files.c:149,209,
#     chirp/src/chirp_tool.c, deltadb/src/catalog_server.c,
#     dttools/src/jx2json.c, dttools/src/copy_tree.c (bounded, one-shot,
#     or startup-only leaks); makeflow/src/dag_visitors.c:404 and
#     makeflow/src/makeflow_linker.c (one-shot makeflow_linker/viz CLI
#     tools); taskvine/src/manager/vine_manager.c:4099 (manager
#     construction failure -- caller aborts right after anyway);
#     work_queue/src/work_queue.c:5601 (a malloc() failure branch,
#     essentially unreachable).
#   - The remaining ~90 memory-leak/dead-code findings (and the ones newly
#     surfaced or shifted by the round-3 fixes above) were confirmed
#     false positives or genuinely cosmetic: the dominant pattern by far
#     is clang's leak checker not modeling hash_table_insert()/
#     itable_insert() as an ownership transfer (both take a `const void *`
#     value parameter, which defeats the analyzer's escape analysis) --
#     every one of these tables' entries is in fact freed later, either
#     individually on removal or in bulk at teardown. This same blind spot
#     re-flags a few of the round-3 fixes above at their allocation/insert
#     site even though the leak is now genuinely closed (confirmed by
#     both a source read and a clean valgrind run) -- clang just can't
#     trace the free across into the separate function that now performs
#     it. The dead-code findings are almost all the standard
#     `if ((x = call()) COMPARISON)` get-and-check idiom, where the
#     "unused" value was in fact read in the condition itself.

# Confirmed real, but low-impact (left as-is, not fixed):
#   - taskvine/src/manager/vine_manager_get.c:68 -- reads an uninitialized
#     total_bytes before writing it in one call path, but the value is
#     discarded by the caller either way.
#   - makeflow/src/makeflow.c:2245 -- reachable only if rmsummary_create()'s
#     unchecked malloc() fails (OOM).
#   - dttools/src/bitmap.c:615 -- a truncated/malformed SGI RGB image file
#     can leave trailing scanline bytes uninitialized before they're OR'd
#     into pixel data; corrupts displayed pixels, not a crash or OOB access.
#   - resource_monitor/src/rmonitor_helper.c:307,350 -- the START() timing
#     macro reads msg.type before it's set; msg.type is unconditionally
#     overwritten shortly after in every actual call site, so this is inert.
#   - dttools/src/luapatt.c:48,57,65,72,147,265 -- the vendored Lua pattern
#     engine always passes an uninitialized MatchState.L to luaL_error();
#     reachable via a malformed pattern, but the local luaL_error() wrapper
#     ignores that argument and just aborts(). One-line fix available
#     (initialize ms.L in pattern_vmatch(), dttools/src/pattern.c) but not
#     applied yet -- low priority given six identical low-impact instances.

# Left unresolved -- needs deeper tracing than a source read could settle:
#   - dttools/src/bucketing_greedy.c:363 and
#     dttools/src/bucketing_det_greedy.c:373 -- couldn't fully rule out an
#     edge case (a top bucket range coming back "unbreakable" and being
#     omitted from the break-point list) without tracing the full
#     recursive splitting logic.
